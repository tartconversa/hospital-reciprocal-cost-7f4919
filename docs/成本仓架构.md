# 科室责任成本仓：架构与口径实现

本文说明 `costwh` 包如何把 `docs/资料口径.md` 的业务约定落成可运行、可反查的事实。
所有口径均为合成的内部管理约定，不作法定会计或医疗定价。

## 1. 处理链条

```
资料文件 ──receive──▶ receipt/stg_row（暂存+接收历史）
                         │ 整批业务校验（失败整批 rejected，不污染事实）
                         ▼
                     事实层 load_facts(as_of)（按接收截点还原最新行）
                         │ close --period
                         ▼
              compute：费用认可 → 双方核实 → 互供联解 → 分位定点 → 守恒核对
                         ▼
        alloc_round / center_cost / alloc_flow(+basis) / round_exception
                         │ queries + report
                         ▼
   总额核对、中心下钻、费用追踪、服务核实、例外清单、新旧轮差异
```

### 1.1 分次装载（`costwh/ingest.py`）

- 每个文件一次接收（receipt），记录接收次序 `receipt_seq`、SHA-256 摘要、接收时刻与原始行（`stg_row.payload` 整行 JSON 永久保留）。
- 相同摘要不增加事实，记为 `duplicate`；同一记录键的新文件是整行修订，事实层只取该键接收次序最新的行，历史可从 `stg_row` 反查。
- 接收要么整批 `posted` 要么整批 `rejected`：业务校验针对“已入账事实 + 本批”执行，拒收批次不进入事实层、不改变后续结转。
- 校验包括：引用中心存在且在期间内生效、费用金额到分且日期在期间内、容量份额合计恰为 1 且必须含 IDLE 行、
  同一 transfer 双方主数据一致且各只一条、同一供方同期单一计量类、确认必须指向已声明服务、
  IDLE 不承担原生费用也不消耗服务量、禁止供方对自身服务等。

### 1.2 双方服务核实（`costwh/facts.py`）

- 每个 `transfer_id` 合并双方回执：`qty_provider`、`qty_consumer` 独立保留，缺回执是 `None`（未知）不是零。
- 双方不一致时 `status=disputed` 并保留未达（差值）；一致但未经人工核实是 `declared`。
- `matched_quantity` 只来自确认文件（共同认可事实），不取 min、不做折中；`confirmed_qty` 未核实即为 `None`。
- `later_confirmations` 与基础确认是同一事实流的后续接收，不随基础资料自动生效，只有新接收+新一轮结转才改变解释。
- 服务量带独立单位（power=kWh、laundry=kg、repair=hour），与金额分列存表，不跨类型相加。

### 1.3 期间费用形成（`costwh/allocate.py`）

**认可口径**：只有 `kind=expense` 进入费用池；`payment` 是同一义务的现金凭据不重复计入（备查 info）；
`pending` 仅待核、不计入（warning 例外）。内部转入永远标记为转入，不会变成新的原生支出。

**固定池（fixed，保障待命成本）**：保障部门自有 fixed 按 `capacity_share` 一次分给容量表全体消费者
（含 IDLE，份额合计 1；IDLE 行就是显式保留的闲置责任，实际用量为零也不分光给临床）。

**可变池（variable，按实际确认服务量）**：

1. 分母只用已共同认可的服务量；未核实、缺回执的服务不进分母、不当零，同时产生 `open` 例外，整轮只能 `provisional`。
2. 每个保障部门按中心级 `idle_variable_share`（重复容量行是同一比例，不逐行相加）把一份可变池分给 IDLE，
   剩余 `(1-idle)` 按确认量份额分给用方；无确认量且 idle<1 的池存在无出口成本时直接阻断（`unabsorbable_variable`）。
3. 转入成本（无论源自 fixed 还是 variable 池）全部按接受方的可变服务份额/闲置比例继续承担，
   不再套一次固定容量分母；转入不是新增 fixed 预算。

**互供联立**：保障部门之间可互相供能/服务。设 V_i 为部门 i 的可变费用池，

```
V_i = 自有variable_i + Σ_j 固定转入(j→i) + Σ_j (1-idle_j)·q_{j→i}/Q_j·V_j
```

用 Fraction 精确高斯-若尔当求解，与处理顺序无关（有测试用不同接收次序验证结果一致）。
方程奇异意味着互供环路没有临床或 IDLE 吸收出口：记 `unclosable_loop` 阻断，
不制造平衡科室、不丢残差。

**分位定点与尾差**：金额结算到分。先求精确解，再在分位上按“各部门池子=自有+转入（转入按分入账）”迭代到自洽；
每次分摊尾差归同一费用池终端分摊基数最大项，并列按中心键升序，保障部门不充当尾差桶。

**守恒核对**：原生费用合计必须精确等于临床终端 + IDLE 闲置承担（分位相等，非约等），否则阻断。

### 1.4 结转确认与轮次（`alloc_round`）

- 每轮记录期间、事实截点 `as_of_seq`、输入事实哈希 `input_hash` 与状态：
  - `confirmed`：无阻断且无未核实服务量；
  - `provisional`：金额可闭合但存在未核实/缺回执服务量，不能当作完整期间结转确认；
  - `blocked`：存在阻断性例外（容量缺失、不可闭合环路、不可吸收成本、守恒失败），不产出分摊结果；
  - `superseded`：更新一轮可用解释产生后，旧轮标记替代，**结果全部保留**。
- 同一事实截点重复结转为幂等（返回同一轮）；新事实只产生新轮，保证“没有一部分科室沿用旧服务量、
  另一部分已承担新费用”——一轮内所有部门共用同一个 `as_of_seq` 事实快照。

## 2. 事实表与下钻

| 表 | 内容 |
| --- | --- |
| `receipt` / `stg_row` | 接收历史与原始行，整行修订与拒收批次都可反查 |
| `recognized_cost` | 本轮认可的原生费用行（仅 expense），可追到 cost_id 与 underlying_id |
| `center_cost` | 每中心自有 fixed/variable、转入 fixed/variable、转出、终端承担 |
| `alloc_flow` | 每条内部流转：金额（DECIMAL 元）与服务量（DECIMAL + unit）分列，份额为精确分数文本 |
| `alloc_flow_basis` | 流转依据：transfer_id（确认量）、capacity_id（容量份额）或 IDLE_VARIABLE（闲置比例） |
| `round_exception` | fatal/open/warning/info 分级例外，未达回执、待核费用、不可吸收成本分别可见 |

查询入口（`costwh/queries.py`，CLI 同名命令）：

- `total`：全院总额核对（原生=临床+IDLE；内部结转额单列但不进总额；现金/待核单列）。
- `report --center`：临床查直接+共同成本；保障查自有费用、接受的内部服务、对外提供服务；IDLE 查闲置承担。
- `trace --cost`：按原始支出查最终去向，费用池经互供网络解出终端份额后分位分摊；同义务付款/待核凭据一并显示。
- `transfers`：双方声明、共同认可、核实状态与对应流转金额一览。
- `exceptions`：所有轮次（含 blocked）的例外清单。
- `diff`：两轮之间新接收、各中心金额变化，并区分“新资料直接触及”与“牵连影响（本轮无新单据）”，
  同时列出变化的内部流转。

## 3. 边界变更

- 科室合并/服务转院外通过中心生效区间（start/end，左闭右开）表达：新期间校验拒绝向失效中心提供内部服务，
  外包费用作为临床科室的原生 expense 直接承担；历史期间轮次按当时事实快照解释，结果不变（有测试覆盖）。
- 历史截点不可使用较晚才知的值：事实还原严格按 `as_of_seq`。

## 4. 命令一览

```
python3 -m costwh --db warehouse.duckdb receive <文件> --received-at <ISO带时区> [--table 表名]
python3 -m costwh --db warehouse.duckdb receipts
python3 -m costwh --db warehouse.duckdb close --period 2026-10 [--note 备注]
python3 -m costwh --db warehouse.duckdb rounds   --period 2026-10
python3 -m costwh --db warehouse.duckdb total    --period 2026-10 [--round N]
python3 -m costwh --db warehouse.duckdb report   --period 2026-10 --center WARD1 [--round N]
python3 -m costwh --db warehouse.duckdb trace    --cost C2
python3 -m costwh --db warehouse.duckdb transfers --period 2026-10 [--round N]
python3 -m costwh --db warehouse.duckdb exceptions --period 2026-10 [--round N]
python3 -m costwh --db warehouse.duckdb diff     --period 2026-10 [--from-id N --to-id M]
python3 -m costwh --db warehouse.duckdb demo     # 合成资料全流程演示
```

退出码：0 成功（暂结亦为 0 但有明确提示）；1 接收拒收或结转阻断；2 用法/查询错误。
